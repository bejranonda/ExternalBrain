## 5.2 Auth (`src/auth.ts`)

Four mutually-exclusive modes — resolved at runtime from env vars.

### Mode 1: Credentials (default for self-hosted)
```typescript
// Env: ADMIN_USERNAME, ADMIN_PASSWORD_HASH (bcrypt cost 12)
// ADMIN_PASSWORD_HASH is generated by: pnpm hash-admin-password '<password>'

CredentialsProvider({
  credentials: { email: {}, password: {} },
  async authorize(credentials) {
    const user = await db.user.findUnique({ where: { email: credentials.email } });
    if (!user) return null;
    const cred = await db.userCredential.findUnique({ where: { userId: user.id } });
    if (!cred) return null;
    const ok = await bcrypt.compare(credentials.password, cred.passwordHash);
    if (!ok) return null;
    return { id: user.id, email: user.email, name: user.name };
  }
})
```

**Timing safety**: `bcrypt.compare` is constant-time by design. Do not add early exits
based on email existence — always run the compare to prevent timing oracles.

### Mode 2: GitHub OAuth
```typescript
// Env: AUTH_GITHUB_ID, AUTH_GITHUB_SECRET, AUTH_SECRET

// In signIn callback: handle REGISTRATION_REQUIRES_VOUCHER
// Check bp_voucher cookie; if present and valid, claim it and allow signup
// If new user and voucher required but not provided → return false (deny)
```

### Mode 3: Dev shim
```typescript
// Only when ALLOW_DEV_AUTH=true
// Refused in production unless ALLOW_DEV_AUTH_IN_PRODUCTION=true
// Uses DEV_USER_ID to bypass auth entirely (for local testing)
```

### Mode 4: Unconfigured (secure default)
```typescript
// When none of the above vars are set
// Every request to protected routes → 503 auth_not_configured
// This is a feature, not a bug
```

### Auth callbacks
```typescript
callbacks: {
  async signIn({ user, account }) {
    // 1. Find or create User row
    // 2. Check ADMIN_EMAILS list → promote to admin if match
    // 3. Bootstrap personal org + default project (idempotent)
    // 4. If REGISTRATION_REQUIRES_VOUCHER: validate voucher, claim it
    return true;
  },
  async jwt({ token, user }) {
    if (user) token.userId = user.id;
    return token;
  },
  async session({ session, token }) {
    session.userId = token.userId as string;
    return session;
  },
}
```

> **Invariant:** `color: var(--accent)` is **banned** for text. Always use
> `color: var(--accent-text)`. The lime accent `#D8FF3E` fails WCAG AA contrast on any
> light background. `--accent` is only for backgrounds and fills (buttons, badges, borders).

### `src/app/layout.tsx` — pre-hydration inline script

```tsx
export default async function RootLayout({ children }: { children: React.ReactNode }) {
  // Server-side: read bp_lang cookie for SSR-correct i18n (prevents hydration mismatch)
  const cookieStore = await cookies();
  const lang = cookieStore.get("bp_lang")?.value ?? "en";

  const themeScript = `
    (function() {
      try {
        var t = JSON.parse(localStorage.getItem('bp_tweaks') || '{}');
        var theme   = t.theme   || 'dark';
        var accent  = t.accent  || 'lime';
        var density = t.density || 'balanced';
        document.documentElement.setAttribute('data-theme',   theme);
        document.documentElement.setAttribute('data-accent',  accent);
        document.documentElement.setAttribute('data-density', density);
      } catch(e) {}
    })();
  `;

  return (
    <html lang={lang} data-theme="dark" suppressHydrationWarning>
      <head>
        {/* dangerouslySetInnerHTML is safe here — no user data, pure JS constant */}
        <script dangerouslySetInnerHTML={{ __html: themeScript }} />
      </head>
      <body>
        <LangProvider lang={lang}>
          {children}
        </LangProvider>
      </body>
    </html>
  );
}
```

The `suppressHydrationWarning` on `<html>` is required because the inline script mutates
`data-theme` before React hydrates — the server-rendered value will differ.

## 5.4 Core API routes

### Auth routes
- `POST /api/auth/register` — create user + personal org; check `REGISTRATION_REQUIRES_VOUCHER`; hash password with bcrypt cost 12; rate-limit per IP
- `POST /api/auth/forgot-password` — create `PasswordResetToken` (1h TTL); send email; always return 200 (prevent email enumeration)
- `POST /api/auth/reset-password` — validate token + expiry + usedAt; update `UserCredential.passwordHash`; mark token used
- `GET  /api/auth/[...nextauth]` + `POST /api/auth/[...nextauth]` — NextAuth handler

### Oracle routes
```typescript
// /api/oracle/stream — SSE
export async function GET(request: Request) {
  const userId = await getCurrentUserId(request);
  if (!userId) return authErrorResponse(401, "unauthorized");

  const { question, reasoningLevel } = parseQuery(request.url);
  const encoder = new TextEncoder();

  const stream = new ReadableStream({
    async start(controller) {
      for await (const event of askStream(userId, question, { reasoningLevel })) {
        const data = `data: ${JSON.stringify(event)}\n\n`;
        controller.enqueue(encoder.encode(data));
        if (event.type === "done" || event.type === "error") {
          controller.close();
          break;
        }
      }
    },
  });

  return new Response(stream, {
    headers: {
      "Content-Type":  "text/event-stream",
      "Cache-Control": "no-cache",
      "Connection":    "keep-alive",
    },
  });
}
```

### Tokens route (`/api/tokens`)
```typescript
// GET  — list user's tokens (masked: show first 8 chars + "...")
// POST — create token: generate 256-bit random, format as `bp_<hex>`, hash with SHA-256,
//        store hash in MCPToken, return the raw token ONCE (never stored, never shown again)
```

### Knowledge routes
- `GET  /api/knowledge` — list with pagination (apply scope filters from `@brain/core`)
- `POST /api/knowledge` — create via `brain_teach_knowledge` logic
- `PATCH /api/knowledge/[id]` — update text fields; re-embed if trigger/rule changed
- `DELETE /api/knowledge/[id]` — soft delete (`deletedAt = now()`)
- `GET /api/knowledge/[id]/related` — graphEdges for this knowledge row
- `POST /api/knowledge/[id]/promote` — bump stage from `notes → knowledge → wisdom`

### Onboarding scripts (`/api/onboard.sh`, `/api/onboard.ps1`)
Return the shell/PowerShell installer script that wires the MCP server for a given token.
The token is passed as a query param or Bearer. Content-type is `text/plain`; these routes
are public (no auth required — the token is embedded in the script output, not extracted
from session auth).

## 5.6 UI shell and screens

### Shell components (`src/components/shell/`)

- `shell.tsx` — authenticated layout with rail + content area
- `rail.tsx` — left navigation rail (icons + labels)
- `cmd-palette.tsx` — ⌘K command palette (navigate to screens, run quick actions)

### Navigation structure (within `[orgSlug]/[projectSlug]`)
Tabs/screens: Dashboard · Oracle · Skills · Graph · Autoskill · Sessions · Decisions

### Screens (`src/components/screens/`)
- **dashboard**: session summary cards, recent knowledge, connection status widget
- **oracle**: question input → SSE stream → cited answer with `[^K1]`/`[^S1]` markers
- **skills**: skill browser with stage filter (inbox/notes/knowledge/wisdom)
- **graph**: knowledge graph visualization (force-directed, type-colored edges)
- **autoskill**: proposal queue (approve/reject/apply)
- **sessions**: session list with outcome badges + event timeline
- **decisions**: filtered view of knowledge tagged `decision` (decay-exempt, settled facts)

### Design philosophy: Progressive Disclosure
```
Dashboard opens calm  →  one fold reveals "everything"
Autoskill queue only appears  →  when proposals exist
Empty states  →  show a single CTA ("Connect a tool to start")
Modals for depth  →  teach-knowledge, token details, user tweaks
```

Do not surface controls the user doesn't need yet. Earn the surface area.

### Key components to implement

**`token-install-wizard.tsx`**: renders the 11 client snippet generators from
`@brain/core/install-snippets`. Tab per client, syntax-highlighted JSON/shell blocks,
one-click copy. This is the main onboarding deliverable — users should be able to go
from "I have a token" to "my AI client is connected" without reading docs.

**`oracle-view.tsx`**: SSE-based streaming Oracle. Starts a `GET /api/oracle/stream`
request, renders tokens as they arrive, then renders citations as links into the
knowledge/session drawer. Show `groundedness` as a badge (strong/moderate/weak/none).

**`effectiveness-badge.tsx`**: shows `success%` when outcomes ≥ 3; shows `— Untested`
when `effectivenessScore === -1`. **Never show 0% for a row with 0 outcomes.**

**`connection-status.tsx`**: live-polls `/api/dashboard/connection-status` (SSE or
polling). Shows which AI clients are actively connected (recent MCP sessions).

### Settings screens (`/settings/`)
- **`/settings/tokens`** — list tokens, create new, revoke, rotate; inline install wizard
- **`/settings/password`** — change password (current + new + confirm)
- **`/settings/org`** — org name, invite members, manage roles
- **`/settings/projects`** — list projects, set framework/language per project

### Admin screens (`/admin/`) — `role: "admin"` required
- **`/admin/vouchers`** — create voucher codes, set max-uses, disable
- **`/admin/users`** — list users, promote/demote admin, trigger GDPR erase
- **`/admin/audit-log`** — audit trail (read-only)
- **`/admin/cost-ledger`** — Oracle cost per user per day

## 5.7 i18n and tweaks

### i18n (`src/lib/i18n.ts`)
Three locales: `en` (default), `th`, `de`. Structure:
```typescript
type Locale = "en" | "th" | "de";
const translations: Record<Locale, Record<string, string>> = { en: {...}, th: {...}, de: {...} };
export function t(key: string, locale: Locale = "en"): string
```

Locale is stored in `bp_lang` cookie. The `LangProvider` component provides `t()` via
React context. Server components read `bp_lang` directly from the cookie store.

### Tweaks store (`src/lib/tweaks.ts`)
```typescript
// Zustand store persisted to localStorage as bp_tweaks
interface Tweaks {
  theme:   "dark" | "light";
  accent:  "lime" | "coral" | "blue" | "violet";
  density: "spacious" | "balanced" | "dense";
  lang:    "en" | "th" | "de";
}
```

The tweaks modal lets the user adjust these. Changes write to `localStorage.bp_tweaks`
and also set a `bp_lang` cookie for the server-side i18n read.
