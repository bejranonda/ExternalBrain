External Brain

Give your AI a memory that survives the session.

Your coding tools forget everything between sessions. This wires them to a Brain that remembers what you decided and why — then hands it back before you have to re-explain it. Three steps.

5 min to working 10 clients supported One command
1Token

Mint a token

Sign in and open Settings → Tokens, then Create token.

Name it after the machine, not yourself — laptop, work-desktop, ci-runner. You revoke per machine, so per-machine names are what make revocation useful later.

The token is shown once. Only its SHA-256 hash is stored — there is no reveal button and no recovery. If you lose it, mint a new one and revoke the old.

The screen then shows an install command with your token already in it. That command is Step 2 — copy it and skip ahead.

2Connect

Connect your AI tool

One command, whichever tool you use. --client defaults to claude-code.

macOS · Linux · WSL · Git Bash
curl -fsSL https://<your-brain>/api/onboard.sh \
  | bash -s 'bp_…' --client claude-code
Windows PowerShell 5.1+
iwr https://<your-brain>/api/onboard.ps1 -UseBasicParsing | iex
Install-Brain -Token 'bp_…' -Client claude-code

What that command actually does

  1. Writes the config — through your tool's own mcp add where one exists, otherwise by merging into its config file. Your other MCP servers survive, and the file is backed up first.
  2. Proves it works — a real connection and tool call through your network and auth. This is why it can claim success honestly: a config file being written proves nothing about whether the token can actually call anything.
  3. Logs a first session, so your dashboard isn't empty on day one.

Then restart your AI tool. Every one of them reads MCP config only at startup. This is the single most common cause of “I installed it and nothing happened”.

3Talk

Talk to it like a colleague

You never call tools by name. You speak normally, and the installed skill tells your AI which tool to reach for.

You say…What happens
(you start any real task)A session opens; past rules that match get handed to the model before it writes anything
“remember this: we use pgvector, not Pinecone”Saved as a rule — it shows up under Skills
“ask the oracle: how did we solve the migration ordering?”A synthesised answer, with citations back to the rules it used
“find the rule about prisma migrations”Closest matches by meaning. Instant and free — no model call
“what did I do last week on billing?”Past sessions matching those words
“that worked” · “we’re done” · “ship it”Closes the session — this is what makes it learn
The one habit that matters

Say “that worked” when you finish.

An unclosed session teaches the Brain nothing — extraction only fires on close. This is the number one reason a Brain sits empty after a week of real use.

Everything else here is optional. This isn't.

A session, start to finish

what it looks like
You     I need to refactor the auth middleware to use the new
        credentials adapter.

Claude  [opens a session, retrieves matching rules]
        Two of your rules apply here: sessions bind at start,
        and credential checks belong at the repository layer.

You     no — we moved that check to the route handler last month.

Claude  Noted, updating.

You     that worked, we're done.

Claude  [closes the session with what it learned]
        Saved: "credential checks live at the route handler,
        not the repository layer — moved 2026-07."

That correction is now permanent. Next month, on a different machine, it arrives before you have to remember it.

Getting good answers

  • “find the rule about X” — instant, free, no model call. Use it any time you'd otherwise re-derive a past decision.
  • “ask the oracle: …” — slower and billed, but synthesised with citations. Use it when you want reasoning, not a list.
  • Don't ask the Oracle general programming questions. It's your project's memory, not the internet. “How does flexbox work” is a web search; “how did we decide to lay out the dashboard” is the Oracle.

เครื่องมือเขียนโค้ดของคุณลืมทุกอย่างเมื่อจบแต่ละเซสชัน คู่มือนี้จะเชื่อมมันเข้ากับ Brain ที่จำได้ว่าคุณตัดสินใจอะไรไว้และเพราะอะไร แล้วส่งกลับมาให้ก่อนที่คุณจะต้องอธิบายซ้ำ ทั้งหมดสามขั้นตอน

1โทเคน

สร้างโทเคน

เข้าสู่ระบบแล้วไปที่ Settings → Tokens จากนั้นกด Create token

ตั้งชื่อตามเครื่อง ไม่ใช่ชื่อคุณ เช่น laptop, work-desktop, ci-runner เพราะการเพิกถอนสิทธิ์ทำทีละเครื่อง ชื่อแบบนี้จึงทำให้การเพิกถอนมีความหมายจริง ๆ ในภายหลัง

โทเคนจะแสดงเพียงครั้งเดียว ระบบเก็บเฉพาะค่าแฮช SHA-256 เท่านั้น ไม่มีปุ่มดูย้อนหลังและกู้คืนไม่ได้ ถ้าทำหาย ให้สร้างใหม่แล้วเพิกถอนอันเดิม

จากนั้นหน้าจอจะแสดงคำสั่งติดตั้งที่ใส่โทเคนของคุณไว้ให้แล้ว คำสั่งนั้นคือขั้นตอนที่ 2 คัดลอกแล้วข้ามไปได้เลย

External Brain

Gib deiner KI ein Gedächtnis, das die Sitzung überlebt.

Deine Coding-Tools vergessen zwischen zwei Sitzungen alles. Diese Anleitung verbindet sie mit einem Brain, das sich merkt, was du entschieden hast und warum — und es dir zurückgibt, bevor du es erneut erklären musst. Drei Schritte.

In 5 Minuten einsatzbereit 10 Clients unterstützt Ein Befehl
1Token

Token erstellen

Melde dich an, öffne Settings → Tokens und klicke auf Create token.

Benenne ihn nach dem Rechner, nicht nach dir — laptop, work-desktop, ci-runner. Widerrufen wird pro Rechner, und genau deshalb machen rechnerbezogene Namen den Widerruf später überhaupt erst nützlich.

Der Token wird nur einmal angezeigt. Gespeichert wird ausschließlich sein SHA-256-Hash — es gibt keine Anzeigen-Schaltfläche und keine Wiederherstellung. Verloren? Erstelle einen neuen und widerrufe den alten.

Danach zeigt die Seite einen Installationsbefehl an, in dem dein Token bereits eingesetzt ist. Dieser Befehl ist Schritt 2 — kopieren und weiterspringen.

2Verbinden

Verbinde dein KI-Tool

Ein Befehl, unabhängig vom Tool. --client ist standardmäßig claude-code.

macOS · Linux · WSL · Git Bash
curl -fsSL https://<your-brain>/api/onboard.sh \
  | bash -s 'bp_…' --client claude-code
Windows PowerShell 5.1+
iwr https://<your-brain>/api/onboard.ps1 -UseBasicParsing | iex
Install-Brain -Token 'bp_…' -Client claude-code

JetBrains, Visual Studio, Eclipse und Xcode haben keinen festen Konfigurationspfad — füge dort stattdessen das JSON aus der Token-Seite ein.

Was dieser Befehl tatsächlich tut

  1. Schreibt die Konfiguration — über das eigene mcp add deines Tools, sofern vorhanden, sonst durch Zusammenführen mit der bestehenden Konfigurationsdatei. Deine anderen MCP-Server bleiben erhalten, und die Datei wird vorher gesichert.
  2. Beweist, dass es funktioniert — mit einer echten Verbindung und einem echten Tool-Aufruf über dein Netzwerk und deine Authentifizierung. Nur deshalb darf der Befehl Erfolg melden: dass eine Datei geschrieben wurde, sagt nichts darüber aus, ob der Token überhaupt etwas aufrufen kann.
  3. Protokolliert eine erste Sitzung, damit dein Dashboard nicht am ersten Tag leer ist.

Starte danach dein KI-Tool neu. Alle lesen die MCP-Konfiguration ausschließlich beim Start. Das ist mit Abstand die häufigste Ursache für „installiert, aber es passiert nichts“.

Sag „hat funktioniert“, wenn du fertig bist.

Eine nicht geschlossene Sitzung bringt dem Brain nichts bei — die Extraktion läuft erst beim Schließen. Das ist der häufigste Grund, warum ein Brain nach einer Woche echter Nutzung noch leer ist.

Alles andere hier ist optional. Das hier nicht.

Diese Korrektur ist jetzt dauerhaft. Nächsten Monat, auf einem anderen Rechner, kommt sie an, bevor du dich daran erinnern musst.

Wie du gute Antworten bekommst

  • „finde die Regel zu X“ — sofort, kostenlos, kein Modellaufruf. Nimm es immer dann, wenn du sonst eine frühere Entscheidung neu herleiten würdest.
  • „frag das Oracle: …“ — langsamer und kostenpflichtig, dafür zusammengefasst und belegt. Nimm es, wenn du Begründungen willst, keine Liste.
  • Frag das Oracle nicht nach allgemeinen Programmierfragen. Es ist das Gedächtnis deines Projekts, nicht das Internet. „Wie funktioniert Flexbox“ ist eine Websuche; „wie haben wir das Dashboard-Layout entschieden“ ist das Oracle.
